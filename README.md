# Unicode 编码查询

一个功能丰富的 Unicode 字符查询与浏览工具，纯前端单页应用，无需后端服务，开箱即用。

当前版本：**v0.2.30**（更新日志见 README 底部，或打开应用「设置 → 关于本工具」查看）

Gitee：[i-dont-want-to-pick-a-name/unicode-chaxun](https://gitee.com/i-dont-want-to-pick-a-name/unicode-chaxun)

基于 **Unicode 17.0** 标准，内置全部 346 个区块定义。

---

## 功能特色

### 🏠 总览
- 应用首页，集中展示数据统计与快捷入口
- 数据统计：字符条目数、区块数、语言分区数、收藏数、收藏分类数、表情符号数
- 快捷入口：一键跳转到搜索、全部字符、随机字符、分类等所有功能
- 最近动态：最近搜索、最近收藏、最近浏览的字符一览

### 🔍 智能搜索
自动识别输入类型，支持多种查询模式：
- Unicode 编码：`U+4E00`、`0x4E00`、`4E00`（纯数字同样按十六进制解释；超出十六进制范围时自动按十进制，如 `1114111` → U+10FFFF）
- 单个字符优先按字符解释：输入 `a` 得到字母 a 而不是 U+000A
- 按字符查询：输入任意字符即可解析
- HTML 实体：`&#20013;`、`&#x4E2D;`、`&amp;`
- CSS 转义：`\4E2D`
- URL 编码：`%E4%B8%AD`
- 按名称搜索：如 `heart`、`arrow`
- **多码点 Emoji 序列**：国旗 🇺🇳、肤色 👍🏽、组合 emoji 👨‍👩‍👧 等自动识别，显示组合后的完整字符及码点组成

### ⚖️ 字符对比
- 并排对比两个字符的所有属性（各取第一个字符；输入了多个字符会明确提示，不再静默取第一个）
- 高亮差异项
- 支持代理对和不可见字符

### 🔤 替换字 · 找形近字（v0.2.25 起）

输入一个字，列出**肉眼几乎一样、码位却完全不同**的字 —— Unicode 官方叫「易混淆字符 confusables」（UTS #39），域名钓鱼、用户名冒充靠的就是它们。

- 内建常见形近组：拉丁 / 希腊 / 西里尔同形字母（`O` / `Ο` / `О`、`A` / `Α` / `А`）、数字与字母（`0O〇０`、`1lI１`）、汉字形近字（未末、己已巳、戌戍戊戎、辨辩辫瓣…）、各种连字符 / 引号 / 斜杠 / 空白字符、兼容字符（`Ω` 与 `Å`）、数学字母与带圈数字
- 另有两条自动规则：**全角 ↔ 半角**、**兼容分解 NFKD**（① → 1、Ａ → A、ﬀ → ff、Å → Å），老设备不支持 `normalize` 会自动跳过，不影响其它结果
- 每张结果卡显示大字、码位、Unicode 名称；点卡片看详情，「复制」直接拿去替换原文，「对比」把两个字丢进字符对比页看编码差多少
- 字符详情弹窗和字体对比弹层都加了「找形近字 / 替换字」快捷入口；**不联网**、三个端都能用

### 📊 批量解析
- 粘贴一段文本，逐字符解析全部属性（单次上限 2000 个字符/编码，超出会提示并只解析前 2000 个，可分段粘贴，避免超长文本卡死页面）
- 表格展示：码点、UTF-8、UTF-16、HTML 实体、CSS、URL 编码
- 一键复制任意列，**实时复制预览**（切换列/分隔符时即时更新）
- **编码→字符**反向解析：支持 `U+XXXX`、`\uXXXX`、`\u{XXXX}`、`0xXXXX`、HTML 实体（`&#x4E16;`、`&amp;` 命名实体）、CSS 转义（`\4E16`）、URL 编码（`%E4%B8%AD`）、纯十/十六进制，支持混合文本自动提取
- **自定义分隔符**：预设按钮（`/` `,` `␣` `↵` `∅`）+ 自定义输入框，切换模式时保留设置
- 解码模式显示**拼接结果**，支持一键复制
- UTF-8/UTF-16 字节间始终用 `/` 分隔，避免与字符分隔符混淆
- 代理对自动合并（`\uD83D\uDE00` → U+1F600）

### 🎲 随机字符
- 按语言分区随机（中文、英文、日文、韩文、阿拉伯文等）
- 按 Unicode 区块随机（上传新版本 Blocks.txt 后区块列表自动更新）
- 一次生成 200 个随机字符

### 📂 浏览方式

**全部字符**
- 按 Unicode 码点顺序浏览全部有效字符（懒加载按需分页），从 U+0000 开始，控制字符始终包含在内
- 支持跳转到指定页码
- 支持按 Unicode 编码跳转定位，自动高亮对应字符

**分类浏览（手风琴折叠面板）**
- 入口名称「分类」，采用手风琴折叠布局，含两个互斥分组：
- **🌐 按平面（17 个）**：列出 Unicode 17 个平面，每个平面显示码位范围、用途说明、区块数
  - 第 0 平面：基本多语言平面（BMP）
  - 第 1 平面：辅助多语言平面（SMP，含表情、历史文字）
  - 第 2、3 平面：罕用汉字扩展区
  - 第 4–13 平面：预留未分配（显示「暂无区块定义」灰色项）
  - 第 14 平面：辅助特殊用途平面（SSP）
  - 第 15、16 平面：私用区 A/B
  - 点击有区块的平面 → 进入该平面下的区块列表
- **📦 按区块（共 N 个）**：直接列出全部区块（含所属平面标注）
  - 点击区块 → 进入字符浏览（虚拟滚动，DOM 只渲染可视区附近几排，CJK 几万字符的大区块也流畅）
- 同时只展开一个分组，点击标题切换；列表区独立滚动，长列表不影响页面布局
- 上传新版本 Blocks.txt 后，两组数据（平面区块数、区块列表）自动更新
- 区块内提供「返回」按钮，并实时显示 `⭐ X / N 已收藏` 进度

**我的收藏**
- 支持分组视图（按区块 / 按语言）和平铺视图（平铺采用虚拟滚动，收藏再多也不卡）
- 分组视图每组首屏最多渲染 240 格，超出部分点「显示剩余 N 个」再展开，避免收藏上千时整组卡死
- 平铺视图按收藏时间顺序排列（最新收藏的在后面），详情弹窗导航也按收藏顺序翻页

**浏览记录**
- 自动记录最近 200 个查看过的字符

### 📄 字符详情
点击任意字符弹出详情卡片，包含：
- 字符预览 + Unicode 码点（十六进制/十进制）
- 字符名称、所属区块（中英文）、Unicode 类别
- UTF-8 / UTF-16 / HTML 实体 / CSS 转义 / URL 编码
- **🔬 高级属性**（参考 codepoints.net）：
  - 双向类别（bidi）、组合类、镜像
  - 大写 / 小写 / 标题形式（如 Æ → 小写 æ）
  - 分解映射（区分规范分解与兼容分解，兼容分解标注 `<compat>` 等标签并显示组合结果字符）
  - 文字系统（sc，如 Latin · 拉丁文）、文字扩展（scx）、断行类别（lb）——上传 Scripts.txt / LineBreak.txt 后显示
- 字符含义（内置字典 + 用户自定义）
- 字典信息（拼音、笔画、部首）
- 不可见字符特殊标记与警示
- 文字放大预览 + 图片导出（PNG / JPG / WebP / SVG）
- **字符导航**：详情弹窗支持前/后切换，键盘 ← → 也可切换（全部字符视图支持跨页导航）

## 分页与导航

### 左右滑动切栏目（v0.2.3 起）
- 手机上在内容区**从右往左滑** = 下一个栏目，**从左往右滑** = 上一个栏目，顺序和侧边栏从上到下完全一致
- 判定条件：横向位移 > 60px、横向明显大于纵向（1.5 倍）、用时 < 900ms——上下滑动照常滚页面，慢慢拖不算
- 不抢手势：侧边栏本身、输入框 / 文本域、能横向滚动的区域（代码块、宽表格）都不参与
- 防手滑：切完抬手那一下的点击会被吃掉，不会顺手点开一个字符
- 到头有提示（「已经是第一个 / 最后一个栏目」），切完有方向动画 + 底部提示条
- 设置 → 手势导航 里可以整体关掉（记在本机）

### 分页栏
- ◀ 上一页 / 下一页 ▶ 基础翻页
- **一键跳页**：输入页码，Enter 或点击「跳页」立即跳转
- **跳 Unicode**（全部字符视图）：输入十六进制编码，自动定位到对应页并高亮字符

### 详情弹窗导航
- 底部导航栏：◀ 上一个 / 下一个 ▶
- 键盘快捷键：← 上一个 / → 下一个 / Esc 关闭
- 导航位置显示：如 `1,234 / 1,112,064`（全局索引；排除 2,048 个代理码点，包含全部其余码点）

## 个人数据管理

### 收藏功能
- 字符右上角 ★/☆ 图标显示收藏状态（纯状态标识，不可点击）
- **收藏状态与进度**：网格顶部显示 `⭐ 42 / 96 已收藏`，实时反映当前页/当前区块的收藏进度
- **🖱️ 点击收藏模式**：一键切换后，点击字符即直接收藏/取消收藏，不弹详情框（适合快速刷收藏）
- 收藏分类：创建自定义分类，像视频收藏夹一样管理收藏的字符

### 数据编辑
- **自定义字义**：管理模式下编辑字符含义
- **自定义字典**：管理模式下编辑拼音、笔画、部首
- **操作日志**：记录最近的操作行为，便于追溯

### 数据导出/导入
- 支持两种导出方式：
  - **下载**：保存到浏览器默认下载目录
  - **另存为**（Chromium 浏览器）：选择任意保存位置
- JSON 格式，方便备份和分享（含收藏分类、**彩蛋图鉴进度**）
- 个人数据范围：收藏 / 收藏分类 / 自定义字义 / 自定义字典 / 浏览记录 / 最近搜索 / **彩蛋图鉴进度**，导出、导入、清空、同步四处口径一致
- 所有个人数据存储在浏览器 localStorage 中，默认不上传服务器

### 跨设备同步（v0.1.1 新增）

换电脑、换手机时，收藏和自定义字义不用重新攒。入口：**设置 → 🔄 同步个人数据**。

先勾选要带走的内容（共 7 项：收藏 / 收藏分类 / 自定义字义 / 自定义字典 / 浏览记录 / 最近搜索 / **彩蛋图鉴进度**；打勾的才同步，默认勾上前四项和彩蛋图鉴，浏览记录与最近搜索默认不勾），再选一种搬法：

| 通道 | 怎么用 | 适不适合 |
|------|--------|----------|
| **取件码** | 点「📤 生成取件码」，拿到 6 位数字；另一台设备打开本应用、把它输进「📥 领取」 | 两台设备都能上网，图省事 |
| **导出 / 导入文件** | 「💾 导出文件」得到 `unicode-sync-日期.json`，用微信 / 数据线 / 隔空投送到另一台，再「📂 导入文件」 | 不想让数据过任何服务器 |

两条通道的共同点：

- **先看再决定**：领取或导入后不会直接写入，先弹一张对照表，列出每个项目「对方多少条 / 我本地多少条」；**每一项前面都有勾选框，接收方可以再挑一次**（默认全收，也能一键「接收全部」），由你点「合并」或「完全覆盖」
  - **合并**：两边都保留；收藏取并集，同名分类合并，同一条目（同一码点的字义/字典）以对方为准
  - **完全覆盖**：用对方的资料替换本地同类数据，本地独有的会消失
  - 以上两种**都只作用于接收方打勾的项目**，没勾的一个字节都不动
- **后悔药**：执行前自动在 localStorage 存一份全量快照，设置里的「↩️ 撤销上次同步」可退回同步之前
- **两边各挑一次**：发送方挑「传什么」，接收方挑「收什么」，最终只落两边都同意的项目

取件码通道的加密与有效期：

- 内容在**发送方本机**加密后才上传，密钥由取件码经 PBKDF2（SHA-256，120,000 次迭代）派生，再用 AES-GCM 256 加密；服务端只经手密文，**解不开也看不到内容**
- 取件码 **10 分钟**自动过期，**取一次即删**（第二次取返回 404）
- 服务端是 Cloudflare Pages Function（`functions/api/sync.js`）+ KV，只做「存密文 → 凭码取回」这一件事；**不部署这个 Function 时，取件码通道不可用，文件通道照常可用**

> 注意：取件码本身就是解密口令，所以**别把它发到公开群里**。6 位数字的强度只够撑这 10 分钟的一次性传递，不适合长期保管数据。

## AI 助手（v0.1.2 起，可选）

自己接一个大模型，让 AI 帮你解读字符、或者用大白话找字。**默认关闭**，不用就完全不联网。

### 隐私约定

| 项目 | 存在哪 | 谁看得到 |
|------|--------|----------|
| API Key | 你这台设备的浏览器 localStorage | 只有你 |
| 请求 | 浏览器直连你填的接口地址 | 你和接口方 |
| 本应用服务器 | —— | **什么都收不到** |

请求不经过本站任何服务。想验证：开 F12 → Network，看请求的目标是 `api.deepseek.com`（或你填的地址），不是 `unchaxun.pages.dev`。也欢迎直接翻 `index.html` 里 `aiChat()` 那一段，就几十行。

### 怎么配

设置 → 🤖 AI 助手：开开关 → 填接口地址（要填到 `/v1` 那一层）→ 填模型名 → 填 Key → 点「🔌 测试连接」。

走的是 OpenAI 兼容格式 `/v1/chat/completions`，这些都能填：

| 服务 | 接口地址 | 模型示例 |
|------|----------|----------|
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |
| 月之暗面 Kimi | `https://api.moonshot.cn/v1` | `moonshot-v1-8k` |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-flash` |
| 本地 Ollama | `http://localhost:11434/v1` | `qwen2.5:7b` |

### 能用它干什么

- **🤖 解读字符**：开了助手后，字符详情弹窗底部多一个「🤖 问 AI」。它会自动带上这个字符的码点、官方名称、所属区块，以及你本地记的备注，问出读音、含义、词例、容易混淆的近似字。回答流式显示，问过的自动缓存（最多 200 条），同一个问题不重复扣费
- **🔎 AI 找字**：搜索页底部的按钮。不知道码点也能找 —— 描述「三个日叠在一起」「表示天气的汉字」，AI 列出候选字符，点一下直接看详情
- **💬 独立 AI 栏目（v0.2.0 起）**：侧边栏的「AI 助手」页，多轮上下文随便聊，聊天记录存本机
- **📇 回答里的码点可以点（v0.2.4 起）**：AI 回答中出现的 `U+XXXX` 会自动变成「字符 + 码点」的圆角小卡片，点一下直接弹出字符详情，不用复制粘贴
- **📚 AI 能看你的收藏（v0.2.4 起，只读）**：发消息时自动注入一份收藏快照（总数、各分类、分类里的字带码点和官方名、你自己记的备注），可以直接问「我的收藏里都有什么」「生肖分类里有哪些字」。**只有查看权限**，增删改仍只能你自己在应用里操作
- **🖼️ 联网查字形（v0.2.4 起）**：字符详情弹窗新增「联网字形」按钮，从 GlyphWiki（glyphwiki.org）拉官方字形图——本机字体缺字形的 CJK 扩展 B/F/G 区字符终于能看到长什么样了；GlyphWiki 对未收录的字返回近乎全透明的图，应用会画到画布上数墨水、自动识别成「没有字形」
- **👁️ AI 视觉（v0.2.4 起，默认关）**：设置 → AI 助手里的开关。开启后，问句里带码点时应用自动联网拉字形图（最多 3 张）随消息发给模型，AI「亲眼」看过字形再回答，不再「记不准、不敢瞎报」。需要模型支持看图（gpt-4o、glm-4v、qwen-vl-max 等），纯文字模型会报错，报错就关掉；关闭时只发文字，不影响你自己看图
- 面板里还有几个常用追问的快捷按钮；按「停止」随时打断

### 连不上接口怎么办

报错「连不上接口」时，十有八九是对方**不允许浏览器直连**（CORS 策略）。两种办法：

1. **装个浏览器插件解除 CORS**（仅自用场景）
2. **自己部署一个转发 Worker**（推荐）—— 仓库里 `workers/ai-proxy.js` 就是，几十行，两分钟部署完：

```bash
# 1. Cloudflare 控制台 → Workers and Pages → Create → 粘贴 workers/ai-proxy.js 的内容 → Deploy
# 2. Settings → Variables 里加（都可不选）：
#      AI_TARGET    默认转发目标，如 https://api.deepseek.com/v1/chat/completions
#      ALLOW_HOSTS  域名白名单，逗号分隔，如 api.deepseek.com,api.openai.com
#      PROXY_TOKEN  设了之后请求必须带同样的 X-Proxy-Token，防止别人白嫖你的 Worker
# 3. 把拿到的地址填进应用「设置 → 🤖 AI 助手 → 代理地址」
```

这个代理只做一件事：把 `Authorization` 头和请求体原样转给你指定的地址，回答（含流式）原样送回。它不打印、不落盘、不记录你的 Key —— 而且它部署在**你的账号**下，不是我的。

> 安卓 APK 里页面跑在 `file://` 下，多数接口会拒绝这种来源的请求，建议配代理地址；桌面 exe 版可以直连。

## 版本更新提示（v0.1.4 起）

打开应用时（默认开启，可在 设置 → 关于本工具 关掉），它会 GET 一次这个文件：

```
https://unchaxun.pages.dev/version.json
```

拿到里面的 `latest` 跟当前 `APP_VERSION` 比一下，有新版就在顶部滑一条提示，点「看看」能看到更新说明和下载按钮。

### 三个端各给各的下载

| 你用的是 | 「看看」里的按钮 | 会发生什么 |
|---|---|---|
| 安卓版（APK） | ⬇️ 下载新版 APK | 直接安装覆盖，**收藏 / 字义 / 设置都不会丢**（它们在应用数据里，不在安装包里） |
| 桌面版（EXE） | ⬇️ 下载新版 EXE | 替换旧 exe 即可，数据在 `%LOCALAPPDATA%\UnicodeChaxun`，不动 |
| 网页版 | 🌐 打开最新网页版 | 网页本来就是线上最新文件；提示新版一般是浏览器缓存了旧页面，按 `Ctrl + F5` 强刷即可 |

判断方式：UA 里带 `Android` 就是安卓版；跑在 `127.0.0.1` / `localhost` 上就是桌面版（桌面版内置的本地服务就在这儿）；其余都算网页版。

### 它不会偷看什么

- 请求就是一个普通 GET，**不带任何参数、不带设备标识、不带你的收藏和记录**
- `version.json` 里只有版本号、发布日期、更新说明和下载地址，没有统计代码
- 查询结果只在内存里用；落盘的只有两件小事：`unicode_update` 里的「自动检查开关状态」和「你点过以后再说的是哪个版本」
- **不想要就关掉**：设置 → 关于本工具 → 「启动时自动检查更新」。关掉后不点「检查更新」按钮就一次请求都不会发

### 匿名统计与下载计数（v0.2.30 起）

作者需要知道「到底有没有人在用」，所以加了一个能关掉的匿名计数 —— **不接第三方统计**，全在自己这个 Cloudflare Pages 里。

| 接口 | 做什么 | 存了什么 |
|---|---|---|
| `GET /api/stats?action=ping&id=…&v=…&p=…` | 应用启动时打一次 | 随机串的 SHA-1 前 20 位、按天累加的打开次数、版本号计数。**不存 IP、UA、查询内容**，也没有账号 |
| `GET /api/dl?f=apk\|exe\|apk_lite\|exe_lite&v=x.y.z` | 安装包下载：先记一次数，再 302 到 Gitee Release | 按天 + 按版本的下载次数（Gitee 不提供下载次数接口） |
| `GET /api/stats?action=summary&key=…` | 作者自己看汇总（已自动扣掉排除名单） | 需环境变量 `STATS_KEY`，没配就 403 |
| `GET /api/stats?action=devices&key=…` | 列出所有上报过的设备（平台/版本/首见/累计打开） | 用来认出"哪台是我自己的机器" |
| `GET /api/stats?action=exclude&key=…[&set=id1,id2]` | 读写排除名单 | 名单里的设备不计入打开数、设备数、设备总数 |
| `GET /api/stats?action=reset&key=…[&date=YYYY-MM-DD]` | 清掉某天（默认今天）的打开数据 | 测试期抹噪音用，不可恢复 |
| `GET /api/stats?action=refdel&key=…&tag=标签` | 删掉某个来源标签的全部记录 | 自检数据、标签打错时清理 |

- **关掉**：设置 → 关于本工具 → 「匿名使用统计」，关掉后 `statPing()` 直接 return，一次请求都不发（键位 `unicode_stats_off`）
- **看数据**：`bash tools/stats.sh`（脚本从 `~/.workbuddy/uchx_stats_key` 读 key，key 不进仓库）；双击根目录 `看数据.bat` 也行；**可视化面板**：双击根目录 `统计面板.html`（纯 SVG 图表：30 天趋势折线 / 版本分布 / 下载量 / 设备清单 / 每日明细，首次打开输入一次 key，存在浏览器 localStorage）
- **排除自己的设备**：`bash tools/stats.sh devices` 认人 → `bash tools/stats.sh exclude <完整设备ID> <备注>` 加进名单（备注可省略，如 `exclude ad0ce329… Win电脑`）。之后每次打开仍会上报，但报表里会被扣掉（原始值看 `opensRaw` / `devicesRaw`）。要连上报都停掉，就直接在设置里关统计开关
- **宣传来源追踪**：给每个渠道一个带标签的链接，比如 B 站用 `https://unchaxun.pages.dev/?from=bilibili`、V2EX 用 `?from=v2ex`。网页版启动时 ping 会带同源 Referer，服务端只取 `from` 里的字母数字标签（**不存完整网址、不存其它参数、不存 IP/UA**），按天 / 累计 / 独立设备记数，面板「流量来源」和 `tools/stats.sh` 都会单独列出来。APK / EXE 是本地文件、没有页面来源，只统计网页版 —— 所以宣传视频简介里放**网页链接**才看得到效果。清掉某个标签：`action=refdel&key=…&tag=bilibili`
- 统计失败一律静默：断网、KV 挂了、函数报错都不影响应用正常使用和下载

### 维护者视角：发新版要做五件事

1. 改 `index.html` 里的 `APP_VERSION`，**以及 README 顶部的「当前版本」行**（这行只手动更新，漏了就会像 0.1.4 → 0.2.1 那样在仓库首页挂旧版本号）
2. 在 README 底部「更新日志」加新版条目；改仓库根目录的 `version.json`（`latest`、`date`、`notes`、`downloads` 里的链接）
3. **跑一遍语法检查**（提取 `<script>` 后 `node --check`，v0.2.1 的教训：文案里的「\u」会让整个应用起不来）
4. 把 exe / apk / **index.html（改名成 `unicode-chaxun-v<版本>.html` 当源码资产）** 传到 GitHub Releases，tag 用 `v` + 版本号；发布说明记得写（GitHub 手机 App 不显示自动的 Source code 压缩包，说明和 HTML 资产就是手机端能看到的一切）
5. 推送 `index.html`、`version.json`、`README.md`、`_headers` 到仓库，等 Cloudflare Pages 自动部署

`_headers` 给 `version.json` 配了 `Access-Control-Allow-Origin: *`：桌面版跑在 `127.0.0.1`、安卓版跑在 `file://`，跨域读这个文件全靠它。同一份文件也给 `index.html` 配了 `Cache-Control: no-cache`。

## 使用方法

### 直接使用
用浏览器打开 `index.html` 即可，无需安装任何依赖。

### 桌面版（Windows exe）

不想每次开浏览器的话，可以打包成一个本地 exe：

```
build.bat            打单文件 exe → dist\Unicode编码查询.exe（完整版约 43 MB，精简版约 16 MB）
build.bat apk        打安卓 APK  → android\UnicodeChaxun-v*.apk（约 2 MB）
build.bat all        两个一起打
build.bat clean      清掉旧产物重新打
```

桌面版的实现（`desktop/`）：

- **pywebview + WebView2** 开一个原生窗口（Win10/11 自带 WebView2，不用打包浏览器）
- 窗口里跑的是 `127.0.0.1:8731` 上的本地小服务（`desktop/app.py`），**不用 `file://` 的原因**：`file://` 的存储行为在不同内核上不可靠，本地 http 服务的 origin 固定，收藏才存得住
- `private_mode=False` + 数据目录 `%LOCALAPPDATA%\UnicodeChaxun` —— 这是收藏真正落盘的地方
- **重复双击不会开两个「不同网站」**：第二个实例会探测端口上已有的实例并直接连过去；否则两个窗口的 localStorage 是分开的，会让人以为收藏丢了
- 只服务打包进来的文件，路径穿越（`/../`、`%2e%2e` 等）一律 404
- 启动 2~5 秒出窗口；若想要快 10 秒左右的目录版，`python desktop/pack.py --onedir`
- 排查启动问题：设环境变量 `UNICODE_DEBUG_LOG=某文件路径` 再启动，各阶段耗时写进该文件

> 数据独立：exe 的收藏存在 WebView2 的用户目录里，跟浏览器的 localStorage 不互通。想搬数据，用应用内「同步个人数据」的文件通道导出再导入。

### 安卓版（APK）

`android/` 目录，纯 framework 无 Gradle 无 AndroidX：一个 Activity + 全屏 WebView 装进 assets 的 `index.html`。

- 开了 `setDomStorageEnabled`，收藏落在 WebView 的 localStorage
- 返回键：能后退就后退，退无可退再按一次才退出（防手滑）
- 包名 `com.unchaxun.app`，minSdk 21 / targetSdk 34，自签名（`android/keystore/unicode.jks`，**不进仓库**，丢了重装会清数据）
- 版本号从根目录 `index.html` 的 `APP_VERSION` 里直接读，不用两头维护
- 手机连上电脑后可以直接装：`adb install -r android\UnicodeChaxun-v0.1.1.apk`
- 注意：**系统 WebView 太老的手机**（Android 5/6 且没更新过 WebView）可能跑不动新版 JS 语法，Android 7+ 一般没问题

### 部署上线
将 `index.html` 上传到任意静态网站托管服务即可：
- GitHub Pages
- Vercel / Netlify / Cloudflare Pages
- 任意 Web 服务器（Nginx、Apache 等）

只部署 `index.html` 就能用全部查询、收藏、导出功能；**跨设备同步里的「取件码」通道需要额外部署 `functions/api/sync.js`**（Cloudflare Pages Functions），步骤：

1. 在 Cloudflare 控制台建一个 KV namespace，记下它的 ID
2. 在 Pages 项目的 **Settings → Functions → KV namespace bindings** 里，把变量名设为 **`SYNC`**，指向刚建的 namespace
3. 把 `functions/api/sync.js` 一起部署上去（目录结构保持 `functions/api/sync.js`）

验证是否通了：浏览器打开 `https://<你的域名>/api/sync?action=health`，返回 `{"ok":true,"service":"unicode-sync","ttl":600,"kv":true}` 即为正常（`kv` 为 `false` 说明第 2 步的绑定没生效）。

前端默认请求的地址写在 `index.html` 里的常量 `SYNC_API`，换域名时改那一行即可。

### 上传完整 Unicode 数据（可选）
内置数据包含全部 346 个区块定义，但不含每个字符的详细属性。获取完整数据有两种方式：

**方式一：一键在线获取（推荐）**
- 打开设置 → 「从文件更新」→ 点击「🔍 一键在线获取完整 Unicode 数据」
- 应用自动从本站拉取全部 4 个数据文件（UnicodeData / Blocks / Scripts / LineBreak）并解析保存，无需手动下载上传
- 数据与网站版本配套（Unicode 17.0），需联网，视网速数秒到半分钟

**方式二：手动上传文件**
1. 打开设置 → 「从文件更新」
2. 下载以下文件（Unicode 17.0.0）：
   - **UnicodeData.txt**：[https://www.unicode.org/Public/17.0.0/ucd/UnicodeData.txt](https://www.unicode.org/Public/17.0.0/ucd/UnicodeData.txt)（约 2.1 MB，必需：名称/类别/大小写映射/分解映射等）
   - **Blocks.txt**：[https://www.unicode.org/Public/17.0.0/ucd/Blocks.txt](https://www.unicode.org/Public/17.0.0/ucd/Blocks.txt)（约 11 KB）
   - **Scripts.txt**：[https://www.unicode.org/Public/17.0.0/ucd/Scripts.txt](https://www.unicode.org/Public/17.0.0/ucd/Scripts.txt)（约 200 KB，可选：文字系统 sc / scx）
   - **LineBreak.txt**：[https://www.unicode.org/Public/17.0.0/ucd/LineBreak.txt](https://www.unicode.org/Public/17.0.0/ucd/LineBreak.txt)（约 180 KB，可选：断行类别 lb）
3. 在设置面板分别点击对应上传按钮

上传后可获得全部 159,801 个字符的名称、类别、大小写映射、分解映射、双向属性，以及（可选）文字系统与断行类别。数据存储在浏览器 IndexedDB 中。

**上传 Blocks.txt 后会自动更新的功能**：
- 分类浏览（17 个平面各平面下的区块列表、数量、范围、空平面判定）
- 随机字符的区块选择列表
- 总览页的区块数统计
- 字符详情中的所属区块信息

## 数据存储说明

| 数据类型 | 存储位置 | 说明 |
|---------|---------|------|
| 收藏 | localStorage | 收藏的字符码点列表 |
| 自定义字义 | localStorage | 用户编辑的字符含义 |
| 自定义字典 | localStorage | 用户编辑的拼音/笔画/部首 |

| 最近搜索 | localStorage | 最近搜索关键词 |
| 收藏分类 | localStorage | 自定义分类名和字符映射 |
| 操作日志 | localStorage | 最近 200 条操作记录 |
| 动画设置 | localStorage | 动画档位（`unicode_anim`）与速度倍率（`unicode_anim_speed`） |

## 技术栈

- 纯 HTML / CSS / JavaScript（无框架、无依赖）
- CSS Grid + Flexbox 布局
- CSS 变量主题系统（深色/浅色）
- Canvas / SVG 图片导出
- File System Access API（另存为功能）
- IndexedDB 存储 Unicode 数据
- localStorage 存储用户数据
- **虚拟滚动**（窗口化渲染）：区块字符浏览、收藏平铺、收藏分类详情只渲染可视区附近几排格子，占位元素撑出滚动高度，滚动时 rAF 节流更新窗口
- **收藏分组视图**未做虚拟滚动，改为每组首屏限量 240 格 + 手动展开，兼顾实现复杂度与最坏情况下的流畅度
- 内嵌 Brotli 解码器：字典数据以 Brotli + base64 压缩存储（比 zlib 再小 25%），运行时同步解压

### v0.0.4

本版是一次「代码审查问题集中修复」版本，重点在稳定性与数据安全，功能行为不变。

**稳定性 / 健壮性**
- **存储层统一收口**：所有 localStorage 读写改走 `lsGet / lsGetRaw / lsSet / lsSetRaw` 四个函数，带 try/catch 与结构校验。此前 7 处裸 `JSON.parse(localStorage.getItem(...))` 在存储被写坏时会直接抛错，导致整个脚本停止执行、页面全白

**数据安全**
- **上传竞态修复**：上传 / 在线获取前先 `await` 本地 Unicode 数据加载完成。此前在数据还没从 IndexedDB 读出来时点上传，会把空的内存快照写回去，等于清掉已存的 2 MB 字符数据
- **错误文件不再覆盖好数据**：四个上传入口都加了最小条目数校验（如把 Scripts.txt 拖进 UnicodeData 槽位会明确报错并放弃导入）
- **写入失败不再假报成功**：`idbSet` 现在返回布尔值并让调用方检查，IndexedDB 写失败时提示会说明「未能写入本地存储，刷新后需重新获取」
- **收藏先落盘再提示**：配额满时不再出现「星标亮了但刷新就没了」，失败会回滚内存状态
- **导入导出闭环**：导入时逐项校验结构（`favorites`/`history` 必须是数字数组、`favCategories` 的值必须是数组等），坏数据会被跳过并告知，不再把收藏视图弄成永久崩溃；确认文案改为与实际行为一致（文件中存在的项替换，其余保持不动）
- **启动时清洗历史脏数据**：`favCategories` / `favorites` / `history` 加载后过滤非法值
